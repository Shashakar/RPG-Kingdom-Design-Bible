# Visual acceptance evidence

**Status: Proposed review protocol based on existing scene-authoring and visual-audit contracts.**

A scene can compile, bake navigation, and pass tests yet remain visually underdeveloped. Technical validation and creative acceptance are different decisions.

## Review package

| Evidence | Purpose |
| --- | --- |
| Player-facing design intent | Describe the desired experience |
| Before/after views | Show actual changes |
| Gameplay-distance screenshots | Evaluate player readability |
| Reverse and overhead views | Evaluate continuity and spatial craft |
| In-motion notes | Assess camera, collision, navigation, and animation |
| Automated validation | Establish tested technical behavior |
| Known limitations | Identify remaining gaps |
| Human sign-off | Record creative acceptance |

Assess material separation, vegetation, scale, terrain transitions, spatial composition, route clarity, tutorial fit, and cohesion with the approved art sources.

Review outcomes: **Accepted**, **Changes requested**, or **Deferred**, with evidence linked.

The [Scene Authoring Contract](https://github.com/Shashakar/RPG-Kingdom/blob/main/docs/SCENE_AUTHORING.md) still controls what agents may edit. This page grants no production-scene permissions.
