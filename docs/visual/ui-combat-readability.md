# UI and combat visual references

**Status: Functional patterns source-recorded; final graphic language open.**

## Reference sheets to collect

| Surface | Required images | What to judge |
| --- | --- | --- |
| Player HUD | Idle, damaged, low-resource | Health/resource priority and clutter |
| Target frame | Friendly, hostile, invalid/out-of-range | Selection versus combat permission |
| Action bar | Available, cooling down, casting | Affordances, readiness, costs |
| Inventory | Empty, populated, equipment interaction | Scanability and item recognition |
| Restoration panel | Missing resources, ready, completed | Clear requirements and contribution feedback |
| Dialogue/tutorial | First-session prompt with world visible | Readability without hiding the scene |

## Rules

A UI reference illustrates hierarchy and behavior, not approval to copy its artwork or exact layout. Avoid decorative complexity that makes a six-slot starter hotbar or cursor-first targeting harder to understand.
