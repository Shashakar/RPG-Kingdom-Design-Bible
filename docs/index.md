## A game about meaningful recovery

The central transformation is **ruin → effort → renewal**. Adventure makes restoration possible; restoration changes how adventure feels. A rebuilt forge is not merely a different model: it can return a person, restore a service, and enable further exploration.

## Authority and scope

!!! info "Source of truth"
    The [game's product vision](https://github.com/Shashakar/RPG-Kingdom/blob/main/docs/PRODUCT_VISION.md), [world restoration foundation](https://github.com/Shashakar/RPG-Kingdom/blob/main/docs/WORLD_RESTORATION_FOUNDATION.md), and [vertical slice](https://github.com/Shashakar/RPG-Kingdom/blob/main/docs/VERTICAL_SLICE.md) are the source for recorded design direction. The game repository remains authoritative for architecture, runtime behavior, and implementation constraints.

!!! warning "Approval is not implementation"
    A proposal is not approved simply because it appears here. A technical merge is not visual sign-off. This bible labels source-recorded direction, candidate guidance, and open decisions separately.

**Current milestone:** one authored region, one damaged settlement, three to five restorable buildings, a small set of resources, one authored dungeon, one boss, and an observable before-and-after settlement. Multiplayer, procedural worlds, full management, and multiple classes are deferred.
